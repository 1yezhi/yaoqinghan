# 微信小程序邀请函 · 第一版

基于之前的方案实现的第一版原生微信小程序：发起人创建/编辑邀请函，受邀人打开信封、播放音乐、纵向浏览邀请函并提交回执。

## 如何运行

1. 用微信开发者工具导入本目录 `D:\邀请函\code`。
2. AppID 使用 `project.config.json` 中已有的 `wx6e0fedd299a6c785`（或换成你自己的测试 AppID）。
3. 基础库建议 3.18.0 及以上；项目已从 Skyline 切回 WebView 渲染，以匹配方案中的兼容性优先策略。
4. 编译后首页是「我的邀请函」，可以直接打开示例，或新建一份邀请函走完五步编辑器。

> 本机未检测到微信开发者工具，因此未执行模拟器和真机预览；但 WXML/WXSS 已通过官方 wcc/wcsc 编译封装校验，页面模板也用示例数据渲染过。导入后如果出现运行时差异，优先看控制台的文件与行号。

## 第一版已经实现

- **受邀端**：信封封面、点击开启动画、背景音乐渐入/暂停、连续滚动阅读、文字渐显、随内容自适应的版式、相册大图预览、地点卡片与微信地图导航、倒计时、回执底部弹层。
- **发起端**：邀请函列表、新建草稿、五步编辑器（基础/时间地点/内容/主题/回执）、草稿保存、预览、发布、分享好友。
- **输入规则**：必填校验、字数上限、日期/时间/经纬度/截止日期格式校验，以及空内容自动隐藏与段落归一化。
- **回执**：姓名、手机号（可选）、出席/不出席、同行人数、饮食禁忌、留言、隐私同意；同一设备可修改；截止后只读。
- **回执名单**：统计、筛选、搜索式列表、复制 CSV 名单（手机号脱敏）。
- **三套主题**：奶油纸张、现代画廊、新中式；编辑器中可切换。
- **演示资产**：本地 5 张抽象纸张/植物图、1 段 24 秒合成背景音乐，均只用于演示，正式使用请替换为有版权的素材。

## 数据存储（重要）

第一版是**本地数据版**：

- 邀请函、回执保存在 `wx.setStorageSync`，key 为 `invitation_app_v1`。
- 示例邀请函会在首次启动时自动写入本机；换设备打开示例会重新生成同样的示例数据。
- **用户自己创建的邀请函目前只在当前设备可见**。把分享卡片发给另一台手机，对方会看到“邀请函不存在”，因为还没有云端数据。
- 回执也只汇总本机提交的数据。

这是第一版刻意的范围控制：先把页面、动画、音乐、表单和发布流程跑通，再接云端。接云端时只需要替换 `services/invitation-store.js` 的实现，页面和组件不需要重写。

## 关键实现说明

### 信封与入场

`components/envelope-cover` 使用 **分层 PNG + CSS transform**，不依赖 Canvas / Lottie：

- `assets/envelope/` 里是 `body / pocket / flap-front / flap-back / letter / sticker / shadow` 七张透明 PNG，对应红金礼盒信封的各个零件。
- 组件按 750×1000 的虚拟舞台换算成百分比定位；封口翻折、背面翻起、信纸抽出、贴纸淡出全部由 WXSS `@keyframes` 完成，`transform` 只作用于 `view` 图层，不直接改 `image`。
- 信纸最终停在信封口袋上方，底部由 `pocket` 图层遮住，形成“从信封里抽出”的关系。
- 动态姓名、日期、火漆字是独立的文字层（`letter-copy`），不烘焙进图片，开场后 0.95s 渐显；字号按姓名长度降级。
- 动画约 1.5 秒结束，页面随即切到邀请函内容；`motion=reduced` 时不播放位移和翻折。
- 点击只负责开启，不再提供“跳过”；开场过程中再次点击会被忽略。
- 开启时同时播放 `/assets/audio/envelope-open.mp3` 并调用 `wx.vibrateShort`；音效是占位合成音，正式使用请替换为有授权的蜡封/纸张音效。

> 之前尝试过 Lottie + `canvas type="2d"`，但当前基础库/模拟器里 Canvas 加载代码包图片不稳定，会出现画布空白。现已整体改为 WXML 图层方案，视觉效果一致，且不再受 `canvas.createImage` 路径限制。

> 新美术源文件在 `D:\邀请函\美术`，已做透明化、裁切、压缩和分层处理；原图带棋盘格背景和“豆包 AI 生成”水印，未直接打进小程序。

### 音乐

音乐在 `pages/invite/index.js` 中创建，不在组件里创建。点击“轻触开启”时先同步调用 `audio.play()`，再 `setData` 和启动动画，避免丢失用户手势。默认遵循系统静音开关；来电打断、切后台、页面卸载都有处理。示例音乐是本地 `/assets/audio/bgm.mp3`，正式使用请换成有授权的 HTTPS 音频。

### 版式与渐显

邀请函不再是“一章一屏”的 swiper，而是一条连续滚动的长页。`services/invite-layout.js` 在渲染前把章节整理成块：

- 短邀请正文 + 短故事（且故事无配图）合并为一张卡；否则分开。
- 流程不超过 4 项且地点没有坐标时，流程与地址合并为一张“当天安排”卡；有坐标时保留独立地图卡。
- 倒计时、回执、致谢合并为一张收尾卡，信息少时也不会出现三张空旷的整屏。
- 正文按字数分为 sparse / normal / rich 三档，分别调整字号、行距、卡片内边距和文本对齐。
- 没有封面时，首屏使用主题渐变、事件水印（囍 / ∞ / ✦）和圆环装饰，避免大面积空白。
- 相册 1 张整幅、2–3 张网格、4 张以上横向滑动；流程没有备注时自动收紧行距。
- 正文超过 240 字折叠为“阅读全文”，避免长文把页面拉得过长。
- 没有任何内容的地点、相册、故事、流程会自动隐藏。

文字使用 `opacity + translateY` 的渐显，滚动到视口时由页面测量位置触发；同一块内按元素顺序错开 60–80ms。开启“减少动效”时关闭位移和循环动画。

### 输入规则

规则集中在 `services/invitation-rules.js`，编辑器和保存逻辑共用：

- 必填：标题、发起人 A、日期、时间、场地名称、详细地址、邀请正文（至少 6 个字）；回执开启时还有截止日期和信息使用说明。
- 上限：标题 24、发起人 12、副标题 40、城市 10、场地 30、地址 60、正文 600、故事 400、流程标题 16、信息说明 80 等。
- 格式：日期必须是真实日历日期；时间必须是 `HH:mm`；经纬度必须同时填写且在合法范围；回执截止日期不能晚于活动日期；流程时间支持 `9:5` 自动补零为 `09:05`。
- 空内容：段落按空行拆分并去掉空行；空故事、空相册、空流程、空地点不进入受邀端；`0` 音量、空副标题等边界值都有单独处理。

### 地图

受邀端不调用 `getLocation` / `chooseLocation`：有坐标时展示地址卡片、示意图和“打开地图”，点击调用 `wx.openLocation`，失败时自动复制地址；没有坐标时只展示地址卡和复制按钮。发起端可以手填经纬度；当前没有接地理编码服务，后续可在云函数中接腾讯位置服务。

### 回执

`components/rsvp-sheet` 负责表单和校验，`services/invitation-store.js` 负责本地保存。回执按 `invitationId + guestId` 做幂等；同一设备再次提交会覆盖原回执。截止日期由邀请函配置控制。

### 分享

邀请函页配置了 `onShareAppMessage` 和 `onShareTimeline`，分享路径为 `/pages/invite/index?id=...`。首页卡片的分享按钮通过 `data-id` 指定具体邀请函。小程序码生成尚未接入（需要云函数调用 `getUnlimited`）。

- 所有页面/分包路由、`usingComponents`、`require` 路径、本地资源引用检查通过。
- 所有 WXML/WXSS 已通过官方 wcc/wcsc 编译器封装编译。
- 所有 WXML 标签闭合、Mustache 括号、绑定事件处理函数检查通过。
- 所有 WXSS 大括号配对检查通过。
- 用示例数据调用编译后的模板生成函数，页面和组件均能正常渲染。
- 用 mock `wx` 存储跑通了：示例读取 → 新建草稿 → 表单映射 → 保存 → 回执提交/修改 → 发布 → 删除。

## 暂未覆盖 / 后续确认

1. **云端数据与跨设备分享**：需要接微信云开发或 WorkBuddy 云服务；当前是本地存储版。
2. **小程序码**：需要云函数生成并缓存；当前只有好友/朋友圈分享。
3. **图片上传**：当前用 `wx.getFileSystemManager().saveFile` 保存到本机，未上传 CDN，也没有服务端压缩/EXIF 清理/内容安全检测。
4. **邀请函编辑器的高级能力**：章节排序/显隐、多人协作、模板市场、分享海报、双语、座位/餐食细分还没做。
5. **隐私与审核**：上线前需要配置微信用户隐私保护指引（相册/相机、回执信息），并确认类目、音乐/图片版权、UGC 策略。
6. **地图选点**：当前手填经纬度；如要地图选点，建议用 `<map>` 点选 + 服务端地理编码，不依赖 `chooseLocation` 的接口权限。
7. **真机验证**：本机没有微信开发者工具，信封图层在 iOS/Android 上的 `transform` 表现、音效与 BGM 混音、震动、地图跳转、相册选择、回执键盘顶起等都需要在真机上再验一遍。
8. **开信音效**：`assets/audio/envelope-open.mp3` 是按蜡封+纸张声合成的占位音，正式使用请替换为有授权的素材。
9. **包体**：信封分层 PNG 约 660KB，已移除 Lottie 播放器（约 205KB）；主包约 1.1MB，后续加素材仍需控制在 2MB 内。

## 重置演示数据

在微信开发者工具控制台执行：

```js
wx.removeStorageSync('invitation_app_v1')
```

重新编译后会重新生成示例邀请函。
